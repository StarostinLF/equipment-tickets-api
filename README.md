# Equipment Maintenance Tickets API

REST API для учёта оборудования производственной площадки (например, ветропарка)
и заявок на его техническое обслуживание. Сервис контролирует жизненный цикл
заявки и позволяет оценить погодные условия на объекте перед планированием
наружных работ.

Данные на этом этапе хранятся в памяти процесса с сохранением снэпшота в
JSON-файл — подключение БД запланировано отдельным этапом. Доступ к данным
выполняется только через слой репозитория, поэтому замена хранилища не
затронет остальной код.

## Требования к окружению

- Node.js 24 LTS (см. [.nvmrc](.nvmrc))
- npm (устанавливается вместе с Node.js)

## Установка и запуск

```bash
npm install
cp .env.example .env
npm run dev
```

Сервис поднимется на `http://localhost:3000` (порт настраивается через `PORT`).
Переменные окружения загружаются нативным флагом Node.js `--env-file-if-exists`
(см. `package.json`) — отдельная зависимость вроде `dotenv` не нужна. Если файла
`.env` нет, сервис возьмёт значения по умолчанию из [src/config/env.js](src/config/env.js)
или переменные окружения, заданные снаружи (актуально для production).

Команда `npm start` запускает сервис без автоперезапуска при изменении файлов —
для этого используется `npm run dev`.

## Переменные окружения

| Переменная | Назначение | Значение по умолчанию |
|---|---|---|
| `PORT` | порт HTTP-сервера | `3000` |
| `NODE_ENV` | режим работы: `development` \| `production` \| `test` | `development` |
| `CORS_ORIGINS` | список разрешённых origin для CORS через запятую | пусто |
| `RATE_LIMIT_WINDOW_MS` | окно ограничения частоты запросов, мс | `60000` |
| `RATE_LIMIT_MAX` | максимум запросов на IP в окне | `100` |
| `WEATHER_API_URL` | базовый URL внешнего погодного API (Open-Meteo, без ключа) | `https://api.open-meteo.com/v1/forecast` |
| `REQUEST_TIMEOUT_MS` | таймаут запросов к внешним сервисам, мс | `5000` |

Полный список с комментариями — в [.env.example](.env.example).

## Структура проекта

```
src/
  app.js            сборка Express-приложения (без запуска сервера)
  server.js         точка входа: чтение конфигурации и запуск HTTP-сервера
  config/           конфигурация (переменные окружения, логгер)
  routes/           маршруты, сгруппированные по ресурсам
  controllers/       разбор HTTP-запроса и формирование ответа
  services/          бизнес-логика
  repositories/       доступ к данным
  middlewares/       request-id, логирование, валидация, обработка ошибок
  validators/         схемы валидации запросов
  errors/             типы ошибок приложения
docs/postman/         экспортированная коллекция Postman
```

`app.js` не запускает сервер — модуль `createApp()` можно подключать
в тестах (Jest + Supertest) без поднятия реального порта.

## Эндпоинты

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/health` | проверка доступности сервиса |

Остальные эндпоинты (оборудование, заявки, прогноз погоды) добавляются
следующими Pull Request'ами по мере реализации.

## Формат ответа

Успешный ответ с одним объектом:

```json
{ "data": { "...": "..." } }
```

Успешный ответ со списком (с метаданными пагинации — появятся вместе с
списочными эндпоинтами):

```json
{ "data": [ ], "meta": { "total": 0, "page": 1, "limit": 20 } }
```

Ответ об ошибке — единый формат для всего API:

```json
{
  "error": {
    "code": "NOT_FOUND",
    "message": "Маршрут не найден: GET /api/unknown",
    "requestId": "b1f2c3d4-..."
  }
}
```

`requestId` присутствует в каждом ответе об ошибке и дублируется в заголовке
`X-Request-Id` — по нему запрос можно найти в логах сервиса.

## Порядок middleware

1. `requestId` — назначает `req.id` (или берёт из заголовка `X-Request-Id`
   клиента), чтобы и логгер, и обработчик ошибок могли на него ссылаться.
2. `requestLogger` (pino-http) — логирует метод, путь, код ответа и
   длительность каждого запроса вместе с его id.
3. `express.json()` — разбор тела запроса с ограничением размера.
4. Роуты — внутри каждого подключена валидация конкретного эндпоинта.
5. `notFoundHandler` — несуществующие маршруты отдают 404 в общем формате
   ошибки.
6. `errorHandler` — центральный обработчик, всегда последний в цепочке.

## Безопасность

Настраивается отдельным этапом (CORS, rate limiting, helmet) — раздел будет
дополнен.

## Тестирование в Postman

Коллекция лежит в [docs/postman/equipment-tickets-api.postman_collection.json](docs/postman/equipment-tickets-api.postman_collection.json)
и использует переменную `{{baseUrl}}`. Пока содержит только проверку `/health`,
будет дополняться вместе с эндпоинтами.
